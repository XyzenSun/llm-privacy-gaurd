### 开发背景与初衷

在我们平时使用 AI 时，许多 AI 供应商明确说明自己会把用户数据保存，或者拿去训练（有些提供商声称自己不会保存用户数据，但被脱库的数据中发现了用户的聊天记录）。

也就是说，我们与 AI 对话的记录对于提供商是可见的，这引入了一个**安全问题**：我们在与 AI 聊天中，很容易泄露隐私。
*   **场景示例**：帮我写一个 SSH 登录命令，IP 为 `123.123.123.123`，密码为 `123456`。

虽然技术层面上，我们可以使用跳板机等解决，但不是所有人都有这个意识，同时，不是所有 AI 的使用者都有计算机基础。如果提供商将我们的数据进行提取，甚至转售给黑灰产业，可能会导致个人信息被提取甚至财产被盗。

因此，我们需要一种方法，保证自己在使用LLM时的个人数据安全，本项目与上文提到的利用技术手段如数据隔离，内网隔离等方法不同，具体的实现请看下文

## LLM Privacy Gaurd 核心设计思路


### 核心角色定义

在本项目中，定义了两个角色：

1.  **可信 LLM**：本地部署，或你信任的提供商（例如你相信Google Vertex AI的承诺，数据不存储，立即删除）。
2.  **云端 LLM**：我们平时使用的 LLM API 提供商，明确说明会使用用户数据，或未明确说明是否使用用户数据，或说明不会使用用户数据，但用户无法验证。

---

### 为什么选择“可信 LLM + 云端 LLM”的混合模式？

大家可能想到，这些云端LLM可能数据泄露，那我本地部署不就好了？但此时也有一个问题：
*   **硬件资源限制**：本地部署一个 AI 模型需要强大的硬件资源。例如部署一个 GLM-5 这种大模型，需要多计算卡阵列，大多数普通用户没有这个条件。
*   **模型闭源**：许多模型并不开源，无法本地部署。

所以，我们不应因噎废食地放弃云端 LLM，而是将其与可信 LLM 结合：
1.  在**可信 LLM** 中，将对话中的隐私数据进行遮蔽。
2.  将遮蔽后的对话数据发送给**云端 LLM**。
3.  云端 LLM 返回结果后，由**可信 LLM** 将结果中的隐私数据替换还原，返回给用户。

这样，既保证了用户的隐私，又保证了 AI 的可用性。

---

###  传统脱敏方法的局限性

既然目的是防止隐私泄露，为什么不用词库（如 ToolGood.Words）将敏感信息去除，或使用某种可逆加密算法替换 Prompt 中的隐私信息，再做后处理，将响应中的加密信息还原。

这种方法虽然有成熟的生产级服务，但有一个缺点：**加密后的数据，AI 还能理解你的意思并实现你的目的吗？**

以“生成 SSH 登录命令”为例，对比原始 Prompt 与 MD5 加密后的效果：

####  原始 Prompt 效果
*   **Prompt**：帮我写一个 SSH 登录命令，IP 为 `123.123.123.123`，密码为 `123456`。
*   **LLM 回复**：
    > 在 Linux 或 macOS 的终端中，最常用的 SSH 登录方式如下。请注意：标准的 SSH 命令出于安全考虑，不支持直接在命令中携带密码...
    > ```bash
    > ssh root@123.123.123.123
    > ```

#### 加密后的 Prompt 效果
*   **Prompt**：帮我写一个 SSH 登录命令，IP 为 `CCDD8D3D940A01B2FB3258C059924C0D`，密码为 `E10ADC3949BA59ABBE56E057F20F883E`。
*   **LLM 回复**：
    > 关于 IP：`CCDD8D3D940A01B2FB3258C059924C0D` 是一个 32 位的十六进制字符串，正常的 IP 应该是像 `192.168.1.1` 这样的格式...
    > 如果这是一个特殊的系统环境... 命令如下：
    > ```bash
    > ssh root@CCDD8D3D940A01B2FB3258C059924C0D
    > ```

**结论**：造成这种差异的原因是加密算法会丧失原本的语义信息，影响 LLM 生成的结果。

---

### 本项目的核心思路：语义化替换


我们让一个可信的 LLM 理解原始 Prompt 的语义，做出**语义化替换**。例如：
*   将 `我的 IP 为 123.123.123.123` 替换为 `我的 IP 为 {IP_ADDR}`。

这样，云端 LLM 就能理解我们的意思，并做出正确的回复。

#### 不足与对策：
1.  **理解能力限制**：可信 LLM 理解能力有限，替换的语义可能不准确。
2.  **云端 LLM 对语义化变量的疑惑**：云端 LLM 看到 `{IP_ADDR}` 会认为这是一个变量，可能会在回复中说“我看到你给的 IP 地址是一个变量”。
    *   **对策**：通过在发给云端 LLM 的 **System Prompt** 中进行说明：*“`{$}` 为变量，你无需提示我需要对他进行替换处理，在你的输出中，只需要输出对应的变量即可，不用为我解释。”*
